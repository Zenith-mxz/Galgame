# 视觉小说（Galgame）· 开发前准备文档

> 项目定位：一款以剧情为核心的视觉小说（Galgame），玩家通过阅读剧情、在关键节点做出选择，基于好感度与旗标触发分支，最终抵达不同结局（含攻略角色线与个人线）。
>
> 文档版本：v1.0（开发前规划稿）
> 本文档为"做之前先把该定的定下来"的规划稿，用于在写第一行代码之前对齐**剧情结构、系统边界、数据结构、美术音频资产与工程规范**。

---

## 一、项目总览与范围界定

### 1.1 项目核心要素

| 维度 | 说明 |
| --- | --- |
| 作品类型 | 纯文字推进的视觉小说（ADV），以立绘 + 背景 + 文本框 + 分支选择为主要呈现 |
| 目标平台 | Windows PC 优先（Steam / 直接发行包）；后续视情况移植 Android/iOS |
| 目标时长 | 单周目 2~4 小时，全结局达成（含全部路线）8~15 小时（需拍板） |
| 目标玩家 | 喜爱剧情向、情感向的作品；通常带有多线攻略与多结局 |
| 付费模式 | 一次性买断（含后续 DLC/剧情追加包的可能性，首版不做） |
| 项目规模 | 小型独立团队（1 名程序 + 1 名策划/编剧 + 1~2 名美术 + 1 名音频，可兼任） |

### 1.2 本次范围（必须明确"做/不做"）

**本期核心（In Scope，必做）**
- 剧情演进系统：对话播放、立绘切换、背景切换、CG 插入、音乐/音效播放
- 选项与分支：选项触发、好感度变更、旗标（Flag）记录、分支跳转
- 存档/读档：多存档位、自动存档、快速存档、回看（Backlog）
- 多结局系统：结局判定、结局解锁记录、结局列表页
- 设置：文字速度、自动播放、音量（BGM/SE/语音分轨）、全屏/窗口、跳过已读
- 主菜单、标题画面、章节/线路选择（视结构而定）
- 已读文本跳过（Skip 已读）、按键快捷操作（Ctrl 跳过、空格/回车推进、Esc 呼出菜单）

**本期外（Out of Scope，首版不做）**
- 多语言（中文之外的语言版本）—— 首版仅中文，但**文本需外置**以便后续扩展
- 全语音（全程配音）—— 首版仅关键场景语音或不做语音
- 3D、Live2D 动态立绘（若做成可选加分项，需单独立项评估成本）
- 云存档、Steam 成就/创意工坊集成（可作为上线前加分项，但需排期）
- 手机端适配与竖屏布局
- 粉丝二创/模组系统

> 建议：首版锁定"**单平台 + 单语言 + 线性主剧情 + 3~5 个结局 + 2~3 条攻略线**"，把系统做稳做扎实，而不是一上来就做成庞大分支树。

## 二、剧情与内容设计（核心）

> Galgame 与普通软件最大的区别在于：**剧情结构本身就是最重要的"架构"**，必须先把剧情骨架定下来，代码才能定结构。本章是全文最优先的章节。

### 2.1 世界观与角色设定
- 一句话故事梗概（Logline）：主角是谁、身处何地、遇到了什么问题、情感主线是什么
- 世界设定：时代、地点、是否含奇幻/科幻等设定要素，需有统一的"设定集"文档
- 角色表（每位角色至少包含）：
  - 姓名 / 称谓（含玩家可自定义主角名时的处理方式）
  - 立绘差分：表情（普通/笑/羞/怒/惊/哭…）× 服装（校服/私服/泳装…）× 姿势
  - 角色定位：是否可攻略、是否为主要配角、是否有专属BGM
  - 声线设定（若做语音）
  - 角色色板（便于美术统一，也便于 UI 文字色与名牌区分）

### 2.2 剧情结构设计（分支图）
**必须先画出分支流程图（Flowchart）**，建议用图工具（draw.io / Figma / 手绘）产出：

```
共通线（Prologue / 序章）
   │
   ├─ 选项A → 好感+  → 进入 角色A 线
   ├─ 选项B → 好感+  → 进入 角色B 线
   └─ 选项C → 好感+  → 进入 角色C 线
                          │
                          ├─ 真结局（True End）
                          ├─ 普通结局（Normal End）
                          └─ 坏结局（Bad End）
```

**分支设计原则**
- 每条攻略线必须有明确的"**进入条件**"（好感度阈值 / 关键选项组合 / 旗标），且这些条件必须是**数值化**的，不能靠剧本口述
- 线路之间的人格一致性优先于戏剧性：避免角色性格因分线而崩坏
- 结局数量统计表：总结局数、真结局数、各线结局数，明确"全结局达成方式"
- 明确"**是否周目继承**"（二周目好感度是否继承、是否解锁隐藏选项）

### 2.3 剧本规格与格式约定
- 剧本以**表格或脚本格式**书写，方便程序解析与文案修改（推荐先定格式再开写）
- 每段剧本行需包含：说话人、文本内容、立绘表情、背景、BGM、SE、演出指令（震屏/淡入淡出/CG）
- **文本长度上限**：对话文本框单屏建议 ≤ 60~70 个中文字符，超过则拆行或分页（UI 需定好换行规则）
- 标明"可跳过/不可跳过"（如生气场景的短演出不宜跳过）
- 台词风格与语气规范（每个角色的口癖、称呼方式需写成表，避免多编剧风格漂移）

### 2.4 剧本工程量估算（用于排期）
- 文本字数估算（中文按"字"计，不要用"页"计）：场景数 × 平均字数
- 每个立绘差分、CG、背景、BGM 的**使用清单**（列出编号，便于美术/音频承接与核查）
- 谁写、谁校对、几轮修改，需明确责任人

## 三、功能需求分析

### 3.1 核心剧情播放系统（Dialogue Engine）
- 依次播放剧本行：显示说话人 + 文本，按文字速度逐字显示（打字机效果）
- 打字机效果可被点击/按键**立即补全整句**（重要交互细节，勿遗漏）
- 推进方式：点击屏幕 / 空格 / Enter / 鼠标左键；自动播放模式可自动推进
- 文本溢出处理：超出文本框时显示"继续指示器（三角/箭头）"或分页

### 3.2 演出与表现（Presentation）
- **立绘系统**：显示/隐藏、更换表情、位置（左/中/右）、进出场动画（淡入/滑入/跳变）
- **背景系统**：切换背景、淡入淡出转场、时间与季节差分
- **CG**：全屏 CG 插入，CG 在"鉴赏模式"中出现需登记到 CG 列表
- **镜头与特效**：屏幕震动、闪白、黑屏停顿、慢速淡出；首版做少量基础特效即可
- **BGM / SE / 语音**：背景音乐循环、淡入淡出切换、音效叠加、语音与台词同步
- **文字框样式**：普通文本框、内心独白样式、旁白样式，需在不同"说话人类型"下切换

### 3.3 选项与分支系统（核心）
- 选项弹出时暂停文本推进，多个可选项按钮纵向排列
- 选项可携带**隐藏效果**：修改好感度、设置 Flag、后续文本可见性
- **好感度/参数面板**（可选展示给玩家，或做"好感度隐藏"的选项）
- **旗标（Flag）**机制：布尔或数值型，供后续条件判断使用
- 条件分支：根据好感度与 Flag 决定后续场景（例如 `if flag_A >= 1 then goto scene_xx`）
- **可选"选项影响提示"**：是否给玩家显示"这个选项会影响后续"，首版建议不显示（保持悬念）

### 3.4 存档 / 读档 / 回看
- **多存档位**：建议 20~40 个槽位 + 自动存档 + 快速存档（Quick Save / Quick Load）
- 存档缩略信息：章节名、存档时间、当前背景缩略图（**强烈建议**做缩略图，否则后期体验差）
- 存档结构必须**向后兼容**：老存档在新版本中可识别，未知字段给默认值
- **Backlog（剧情回看）**：可回滚查看已读文本（通常不做可回滚"重新选择"）
- 是否有"**回滚（Rollback）**"功能：可回退几段剧情，需明确回滚时立绘/BGM 的状态还原逻辑

### 3.5 跳过 / 已读记录
- **已读判定**：同一剧本行首次阅读后记入已读表（按剧本行唯一ID），Skip 模式只跳已读，避免跳过未读关键剧情
- "跳过已读"与"全部跳过"需分别配置
- 跳过速度可设置（快速/瞬时）

### 3.6 结局与图鉴
- **结局判定**：进入结局节点时按条件判定，显示对应结局 CG / 演职员表
- **结局记录**：已解锁结局列表（未解锁显示"？？？"）
- **内容图鉴**：CG 鉴赏、BGM 鉴赏、（可选）角色资料页——只展示已解锁内容
- **全结局达成奖励**（可选）：解锁隐藏剧情/彩蛋

### 3.7 设置与系统菜单
- 文字速度滑块、自动播放间隔
- 音量：BGM / SE / 语音 / 总音量分轨
- 显示模式：全屏 / 窗口，分辨率选项
- 跳过设置、文字框透明度、是否显示已读标记
- 语言切换（首版仅中文，但软开关保留）
- 退出、返回标题、返回主菜单

### 3.8 主菜单与标题界面
- 标题画面（Title Screen）：开始游戏 / 继续游戏 / 读档 / 图鉴 / 设置 / 退出
- "继续游戏"应默认读取最新存档（自动或手动）
- 若做了攻略线，需有"线路选择/章节选择"入口（是否允许跳章影响剧透，需拍板）

## 四、数据需求（数据结构设计）

> Galgame 的数据主要分为 **静态剧本数据**（写死在资源里）和 **动态运行态数据**（存档/设置）。二者务必分离，脚本数据不进存档、存档只存"状态"。

### 4.1 剧本脚本 `script`（核心）
推荐以 **JSON/自定义脚本语言** 描述每行演出指令。示例思路（每行即一条指令对象）：
```json
{
  "line_id": "ch01_005",
  "speaker": "alice",
  "text": "……今天也要一起走吗？",
  "sprite": { "id": "alice", "emotion": "shy", "pos": "center", "clothes": "uniform" },
  "bg": "classroom_evening",
  "bgm": "bgm_daily_soft",
  "se": null,
  "effect": { "type": "fade", "duration": 0.5 },
  "next": "ch01_006"
}
```
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| line_id | string | 剧本行唯一ID（已读记录、跳转、回滚都基于它） |
| speaker | string | 说话角色ID；空则旁白 |
| text | string | 台词文本（外置为文本资源，便于多语言与校对） |
| sprite | object | 立绘ID/表情/位置/服装 |
| bg | string | 背景ID |
| bgm / se / voice | string | 音频ID |
| effect | object | 演出效果（淡入淡出/震动/闪白） |
| next | string | 下一行（默认顺序，也可为跳转标签） |

> **关键原则**：剧本指令与"文本内容"应分离（文本外置为语言文件/表格）。这样后续加语言、校对修正文案，不用动脚本逻辑。

### 4.2 选项 `choice`
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| choice_id | string | 选项组唯一ID |
| text | string | 选项显示文字 |
| next | string | 选择后跳转的剧本行/场景 |
| effects | object | 触发效果：`affection: {alice: +3}`、`flag: {met_library: true}` |
| hidden | object | 隐藏条件：`require: {flag_x: true}` / `affection: {alice >= 20}` |

### 4.3 角色定义 `character`
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 角色ID（剧本中引用） |
| display_name | string | 显示名（可随剧情变化，需支持"名字带 `?` 未揭示"状态） |
| color | string | 名牌/文字色 |
| sprite_set | object | 表情 × 服装 × 姿势的资源映射表 |
| voice_actor | string | 声优（若做语音） |
| bgm | string | 专属BGM |

### 4.4 存档 `save_slot`
> 存档只存"运行状态"，不存剧本。
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| slot_id | int | 槽位（1~N / auto / quick） |
| script_line_id | string | 当前所在剧本行 |
| affection | map | 各角色好感度数值 |
| flags | map | 旗标集合（布尔/数值） |
| unlocked | object | 已解锁的 CG/结局/BGM 索引 |
| backlog | array | 最近N条回看记录（如50条） |
| sprite_state | object | 当前立绘/背景/BGM 快照 |
| saved_at | datetime | 存档时间 |
| chapter_name | string | 章节名（存档列表展示） |
| thumbnail | string | 存档缩略图路径 |
| version | string | 存档版本号（用于兼容与迁移） |

### 4.5 已读记录 `read_history`
- 建议全局共用（跨存档），存放 `line_id` 已读集合
- 强烈建议单独文件存，不随单存档覆盖，否则换存档后"已读"丢失

### 4.6 全局解锁 `global_unlock`
- 已解锁 CG / 结局 / BGM 使用位置：全局存档（跨周目）
- 与单存档槽位的 `unlocked` 需明确"合并策略"（通常全局并集）

### 4.7 设置 `config`
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| text_speed | int | 文字速度 |
| auto_delay | float | 自动播放间隔 |
| bgm_vol / se_vol / voice_vol / master_vol | int | 音量分轨 |
| skip_mode | enum | 跳过已读 / 全部跳过 |
| fullscreen | bool | 全屏 |
| resolution | string | 分辨率 |
| textbox_opacity | float | 文本框透明度 |
| language | string | 语言（首版 zh-CN） |

## 五、界面布局规划

### 5.1 游戏主界面布局（16:9 基准，建议 1920×1080 设计稿）
```
┌──────────────────────────────────────────────┐
│  [背景]                                        │
│                                                │
│          [立绘 左]     [立绘 中]     [立绘 右]   │
│                                                │
│  ┌────────────────────────────────────────┐  │
│  │  [名牌: 角色名]                          │  │
│  │  台词文本……                              │  │
│  │                                   ▼     │  │
│  └────────────────────────────────────────┘  │
│  [菜单按钮区右下角: 存档/读档/设置/回看/自动/跳过] │
└──────────────────────────────────────────────┘
```

### 5.2 典型页面结构说明
- **标题画面**：主视觉（Key Visual）为主，菜单按钮右下或居中偏下，配标题 BGM
- **游戏内界面**：文本框在下 1/4~1/3 区域，立绘在上 2/3；操作按钮半透明、悬停高亮
- **选项界面**：居中或偏下纵向排列按钮，半透明遮罩弱化背景以聚焦选择
- **存档列表页**：卡片式槽位（含缩略图、章节名、时间），支持分页/滚动；有"自动/快速"分区
- **Backlog（回看）**：半透明全屏列表，向上滚动查看历史台词，可点击角色名
- **设置页**：分标签（文字/音频/显示/系统），滑动条 + 开关 + 下拉
- **图鉴页**：CG/结局/BGM 分 Tab 的网格布局，未解锁为剪影

### 5.3 视觉与交互规范
- **风格**：需与美术风格统一（日系赛璐璐 / 厚涂 / 水彩等），UI 素材与立绘色调需一致
- **配色**：主 UI 以半透明深色文本框 + 角色名牌色为准；强调色统一
- **字体**：正文用易读的中文字体（如思源黑体/思源宋体），标题可定制字体，需**确认字体授权**
- **字距行距**：正文行距 1.4~1.6，字距适度，保证长文本可读性
- **交互反馈**：按钮悬停/按下态；自动播放时有指示；跳过模式有明确"快进中"标记；**避免误触导致选项被选中**
- **响应式**：PC 为主，适配 16:9、16:10；窗口缩放需等比适配（不要出现拉伸变形）

## 六、素材、技术与工程准备清单

### 6.1 美术素材准备（Galgame 资产量最大项）
- [ ] **背景**：白天/傍晚/夜晚差分，CG 场景背景，分辨率 ≥ 1920×1080
- [ ] **立绘**：各角色 × 表情 × 服装 × 姿势的差分清单（**先行出清单再画，避免返工**），建议透明 PNG，控制在 2 倍内
- [ ] **CG**：关键场景 CG（含差分如"微笑/流泪"），并登记进 CG 鉴赏表
- [ ] **UI 素材**：文本框、按钮、手册、名牌、指示箭头、菜单图标（统一风格）
- [ ] **标题画面 / 主视觉 / Logo**
- [ ] **图标**（窗口图标）、**结局标记**、**加载/转场素材**
- 素材命名规范必须统一（如 `alice_smile_uniform.png`），并建立 **资产清单表（Asset List）**，标“已设计/已绘制/已接入/已验收”

### 6.2 音频素材准备
- [ ] **BGM**：日常/紧张/温馨/悲伤/战斗（如有）等场景曲目，注明循环点（Loop Start）
- [ ] **SE**：点击、翻页、心跳、开门、雨声等
- [ ] **标题BGM / 片尾曲 / 主题歌（视预算）**
- [ ] **语音**（若做）：按剧本行标注配音，录音需与行ID对应
- [ ] 授权核查：所有音乐/音效需明确商用授权（避免侵权，上线前必须核查一次）

### 6.3 引擎与技术选型（建议，需团队确认）
| 类别 | 候选 | 说明 |
| --- | --- | --- |
| 引擎 | **Ren'Py** | Galgame 首选，自带存档/回看/跳过/设置等大量现成功能，Python 脚本化 |
| 引擎 | **Unity + Naninovel**（付费插件）或自研 | 若需要更强演出/移植多平台 |
| 引擎 | **Godot** + 自研对话系统 | 开源、轻量，适合无现成插件时 |

| 文本外置 | 独立语言文件/表格（CSV/JSON） | 便于校对与多语言 |
| 版本管理 | Git + **Git LFS**（大文件） | 立绘/CG/音频体积大，必须用 LFS |
| 自动化 | CI 导出构建、资源校验脚本 | 检查缺失素材、脚本语法错误 |

> 建议：若是小团队且目标为 PC 包体，**优先 Ren'Py**——它把存档、跳过、回看、设置、多语言等都做完了，团队可专注剧情与美术。

## 七、待确认问题（开发前必须拍板）

1. **引擎选型**：直接用 Ren'Py，还是 Unity/自研？这决定后续所有系统的工作量与脚本格式。
2. **分支结构**：共通线 + 几条攻略线？每个角色几个结局？是否做真结局？总结局数多少？
3. **好感度阈值规则**：进入某条线需要多少好感度、何时判定、是否允许跨线？必须数值化。
4. **是否做全语音**：决定音频预算与剧本配音标注工作量（首版建议不做或仅关键场景）。
5. **是否周目继承**：二周目是否继承好感度/解锁隐藏选项？影响 Flag 与存档结构。
6. **是否允许回滚（Rollback）**：回滚到上一个选项后重选？这会影响存档与跳过逻辑的设计。
7. **存档位数量与缩略图方案**：缩略图如何生成与存储（关键体验项）。
8. **多语言预留**：尽早将文本外置，避免后期重构。
9. **字体与音乐授权**：上线前必须核查商用授权，是否已明确来源？
10. **发行平台**：Steam 是否为首发平台？是否需要成就/云存档适配（影响排期）。

> 优先级最高的三项是 **1、2、4**：引擎、剧情结构、语音规模，这三项直接决定项目人力与周期，建议在正式开工前开会拍板，避免返工。
